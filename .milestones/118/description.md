Outcome: the wallet is ready for the Dijkstra hard fork — every Dijkstra era
code path implemented and exercised, no `error` stubs and no silently-skipped
era tests — before the fork reaches mainnet.

**The outcome is readiness, not a version number.** Advancing `cardano-node` to
11.1.0 was the assumed means when this milestone was created; the operator has
since ruled it is not the end. This milestone may complete without that advance,
and if it does, that is success rather than a truncation. Conversely, reaching
any particular pin without the era paths working would not close it. A test that
named a version could fail while the product was ready, or pass while it was
not.

**Observable test.** Obtain the published wallet artifact the way a stranger
would, run it against a Dijkstra-capable network, and exercise the paths that
today `error` on Dijkstra: era mapping and conversion, transaction construction
and signing, delegation, UTxO and local-state queries, protocol parameters, and
block processing. Zero Dijkstra `error` stubs reached; zero era tests reported
`pending`.

Static counterpart, enforced in CI and generated by the census script rather
than from a hand-listed set of message strings — the stubs carry at least five
distinct message shapes and some carry no "not yet supported" text at all:

```
error stubs mentioning Dijkstra, counted multi-line-aware  == 0
pendingWith "TODO: Dijkstra"                               == 0
```

The criterion must be demonstrated red against today's tree before any green
from it is believed.

**Artifact.** In flight: the `Nightly vYYYY-MM-DD` pre-release line (tag
`nightly`), clearly marked provisional. It graduates into the
`Release vYYYY-MM-DD` production line when the milestone closes.

**Scope boundaries.** In scope: the Dijkstra era support surface in `lib/`, and
any dependency movement that turns out to be genuinely required to obtain it.
Out of scope: unrelated technical-debt cleanup (milestone #119), the
`cardano-node` 11.0.1 readiness work (milestone #114), and mainnet hard-fork
operations themselves.
