## Rules bound this session, all paid for

- **A PR description is not the diary of your adventure.** No base branch, no
  rebase, no `wip` hygiene, no census/`MAX`/ratchet machinery, no invariant or
  finding IDs, and no status-at-time-of-writing. The checks report status; the
  body describes the change.
- **`INV-19` means nothing in a PR description.** Invariant IDs are lane
  vocabulary; outward text states the property. Includes test names.
- **A commit subject is not a gate receipt.** A `-Werror clean` subject was true
  of one package and false of the project.
- **`MERGEABLE` is not "based on the tip."** It says the merge would be clean,
  not that the branch is current. A branch sat one merge-commit behind `master`
  for hours while that field read green.
- **A rebase of the stack floor silently stops CI above it** — GitHub creates no
  run object for a `CONFLICTING` PR, so the symptom is an *empty check list*,
  not a red mark. The relay after any rewrite is the desk's, and this desk
  failed it twice.
- **A local `cabal build` green does not predict CI**; the nix derivations build
  with `-O2 -Werror`. Legal proxy:
  `nix develop -c cabal build all --ghc-options=-Werror`.
- **Merge authorization is the project owner's**, not this desk's.
